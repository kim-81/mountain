# 산길따라 · 테스트 버전 v0.8.6

서울의 산 8곳으로 시작하는 등산 가이드 앱입니다. Android/iPhone 앱 소스, PC 미리보기, 로컬 계정·일정·후기 서버가 들어 있습니다. Android 15 가상 기기에서 APK 설치, 모의 GPS 기록·복구·저장과 백그라운드 이탈 알림을 확인했습니다. 실제 휴대폰 검증과 iPhone 빌드는 남아 있습니다.

**v0.8.6 추가:** 수락산·불암산·인왕산·북악산의 OSM 참고 경로, 불암산 남쪽 배경지도 보강. 기본 경로 7/8곳, 봉화산 미확보. [검증 결과](docs/v086-서울경로보강.md).

**v0.8 추가:** 주변 시설 2,115곳, 공식 공지와 코스별 통제·우회 공지 우선 표시, GPX 미리보기, 후기 사진 저장과 산행 복구를 개선했습니다. [개발·검증 결과](docs/v08-시설-공지-후기.md).

**v0.7 추가:** 산행 준비 탭의 현재 기온·체감·바람·돌풍·3일 예보를 실제 Open-Meteo API에 연결했습니다. 수신/예보 기준 시각·캐시·연결 실패·오래된 정보 표시를 구분합니다. [날씨 연결 결과](docs/v07-날씨연결.md).

**v0.6:** Android 보호 저장소·HTTPS 통신, iOS Keychain 연결 소스, 휴대폰 세션 인증·공유 링크·연결 상태와 운영 시작 검사를 구현했습니다. **기본 APK에는 아직 공개 서버 주소를 설정하지 않았습니다.** [연결 구현 결과](docs/v06-휴대폰-서버연결.md) · [11월 말 완료 기준](docs/11월말-완료기준.md).

**v0.5:** JSON 기록 가져오기·중복 방지·저장 실패 복구, 기록별 GPX 저장, 삭제 확인 창을 추가했습니다. [기록 보관과 오류 검증](docs/v05-기록보관과-오류검증.md). 자동 검사 37개와 예시 파일의 브라우저 흐름을 확인했습니다. 실기기 GPS 검증은 다음 현장 피드백을 기다립니다.

**v0.4:** Android 기록 파일 저장, 서버 계정 비밀번호 변경·탈퇴·내 자료 내보내기, 요청 오류 처리와 HTTPS 서버 설정을 보완했습니다. [이번 개발 결과](docs/v04-계정과-안정성.md) · [무료·저비용 운영안](docs/서버-운영안.md). 공개 서버는 아직 연결하지 않았습니다.

**v0.3 지도:** 서울 8개 산 주변 OSM 도로·산길·숲 배경지도, 기본 경로 3개(아차산·북한산 종로·관악산), 확대·이동, 배경지도 오프라인 캐시를 구현했습니다. 외부 지도 패키지/타일 서버 없이 공개 지리자료를 직접 렌더링합니다. [이번 개발 결과](docs/v03-지도개발.md)

## PC 미리보기 실행

**Node.js 24 이상**에서 `미리보기.cmd`를 실행하면 브라우저가 열립니다. `npm install`은 필요 없습니다.

PowerShell로 실행할 때:

```powershell
cd C:\Users\User\Desktop\github\mountain
node scripts/serve.mjs
```

브라우저 주소는 `http://127.0.0.1:4173`입니다. 종료는 콘솔에서 Ctrl+C를 누르세요. 이 서버는 내 PC에서만 접속됩니다.

Node를 찾지 못하면 Codex에 포함된 런타임을 직접 지정할 수 있습니다.

```powershell
& 'C:\Users\User\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' scripts/serve.mjs
```

Node 24가 없는 경우 `node scripts/serve-static.mjs`는 서버 계정 없이 화면과 기기 저장 기능만 엽니다. HTML을 더블클릭하면 모듈/오프라인 기능이 제한되므로 HTTP 서버로 실행하세요.

이전 버전이 보이면 새로고침하세요. 서비스 워커 업데이트 직후에는 한 번 더 새로고침이 필요할 수 있습니다.

## 이번 버전에서 사용할 수 있는 기능

- 서울의 산 8곳 검색·필터·조건별 추천·즐겨찾기.
- 8곳의 공식 대표 코스 거리·시간·출발/도착·출처·확인일 표시. 정상 등정 코스와 둘레길 구분.
- 코스 정보 / 산행 준비 / 주변 시설 / 후기·사진 탭과 준비 체크리스트.
- GPX 미리보기와 저장, 다중 구간 유지, OSM 배경지도 위 경로·GPS 기록 표시.
- 기본 경로 3개와 다른 5개 산의 배경지도, 확대·드래그·방향키 이동·범위 밖 안내.
- 실제 GPS 위치·이동 경로·거리·시간 기록, 종료 시 완주 직접 확인.
- 진행 중 기록 보관, 재실행 후 이어가기/종료 저장. 긴 GPS 공백을 직선거리로 더하지 않음.
- 가져온 경로 기준 이탈 판정. Android/iOS 백그라운드 알림 소스 포함하나 **실기기 검증 전**.
- 로컬 서버에서 별명·테스트 비밀번호로 계정 등록/로그인.
- SQLite에 일정·참가 응답·후기·사진 저장, 같은 서버의 여러 계정에서 응답 확인.
- 서버 일정의 참가자 목록 10초 갱신, 작성자만 일정/후기를 수정·삭제.
- 즐겨찾기·완주 이력을 반영하는 추천과 기기 내 개인 기록의 계정별 구분.

서버 계정의 계정 관리에서 비밀번호 변경·내 자료 내보내기·탈퇴를 할 수 있습니다. Android APK에서는 기기 기록 파일 내보내기를 사용할 수 있습니다. 나의 산행에서 기록 JSON 가져오기와 기록별 GPX 저장을 지원합니다. 계정·사진·일정 전체 복원은 지원하지 않습니다.

## 먼저 알아둘 제한

**실제 산행 길 안내용으로 검증이 끝난 앱이 아닙니다.**

1. 기본 경로는 OSM 기여자 자료 3개이며 현장 미검증입니다. 다른 5개 산은 사용자 GPX로 경로를 추가할 수 있습니다. 도로·산길·숲 배경은 제공하지만 등고선·고도 지도는 포함하지 않습니다.
2. 공식 안내 수치는 2026-11-04에 확인했습니다. 오늘의 통제 상태와 실제 현장 상태를 검증한 것은 아닙니다.
3. 대표 지점 날씨와 기관 공지를 표시합니다. 개별 코스 개방 여부는 공식 원문에서 확인하세요. 시설과 식당의 영업 상태는 현장에서 확인해야 합니다.
4. Android 가상 기기에서 설치와 모의 GPS를 검증했습니다. 휴대폰의 화면 잠금·절전, 실제 GPS·알림, 파일 선택과 iPhone 빌드는 남아 있습니다.
5. 서버는 로컬 전용입니다. 다른 휴대폰이나 외부 사용자와 공유하려면 공개 HTTPS 서버 개설·주소 설정·실기기 인증 검증이 필요합니다. 네이티브 앱의 기본 상태는 기기 저장 모드입니다.
6. 웹 오프라인 캐시에 서울 대상 지역의 배경자료와 기본 경로를 포함합니다. 첫 접속 후 자료 저장이 끝나야 하며 저장 범위를 벗어나면 표시가 제한됩니다.

서버 계정은 사용자가 Railway 무료 체험으로 준비하기로 했습니다. iPhone 설치 파일 생성에는 추가 Mac 환경이 필요합니다. [Railway 연결 준비](docs/Railway-연결준비.md).

현재 상태는 [개발현황](docs/개발현황.md), 데이터 기준은 [데이터구성](docs/데이터구성.md)에 정리했습니다.

## 직접 확인해 볼 순서

1. 오른쪽 위 계정 버튼에서 ‘테스트 계정 만들기’를 선택합니다. 실제 개인정보와 다른 서비스에서 쓰는 비밀번호를 입력하지 마세요.
2. 아차산을 검색하고 공식 안내 수치와 출처를 확인합니다.
3. ‘산행 준비’ 탭에서 준비 항목을 체크합니다.
4. 본인이 이용할 수 있는 GPX를 가져옵니다. `tests/fixtures/기능검사용-가상경로.gpx`는 테스트 전용이며 실전 사용 금지입니다.
5. 코스를 선택하고 일정을 만듭니다. 다른 브라우저에서 두 번째 테스트 계정으로 공유 링크를 열고 참가하면 첫 계정의 참가자 목록에서도 응답이 보입니다.
6. 산행 GPS는 위치 사용을 허용한 실제 기기에서 검증합니다. 기록을 시작하고 종료해 완주 여부를 선택합니다.

## Android / iPhone 실행

- Android: Android Studio에서 `android` 폴더를 엽니다. JDK 17·Android SDK 35·AGP 8.7.3·Gradle 8.9·Kotlin 2.0.21 구성입니다. 필요하면 `android`에서 `.\gradlew.bat --version`으로 공식 Gradle 배포본을 준비한 뒤 Sync하고 Run합니다. 성공적으로 빌드하면 `android/app/build/outputs/apk/debug/app-debug.apk`가 생성됩니다. 이번 PC에서는 프로젝트 전용 도구를 준비해 APK를 생성했습니다. 다시 빌드하려면 프로젝트 폴더에서 `node scripts/sync-native.mjs`, `node scripts/build-android.mjs`, `node scripts/verify-android.mjs`를 순서대로 실행합니다.
- iPhone: Mac의 Xcode에서 `ios/SeoulTrail.xcodeproj`를 열고 자신의 Team과 Bundle Identifier를 설정합니다. iOS 16 이상 기기를 선택하고 Run합니다. 위치 권한과 Background Modes의 Location updates를 확인하세요.
- 코드에 개발 계정·서명 인증서·공개 서버 주소를 임의로 넣지 않았습니다.

## 외부 의존성

UI·웹 서버·GPX 계산에 제3자 패키지를 추가하지 않았습니다. Node.js 내장 HTTP·SQLite·암호화와 브라우저/Android/iOS 기본 API를 사용합니다. SQLite는 로컬 계정·일정이 서버 재실행 뒤에도 유지되도록 사용합니다.

Android 빌드에는 공식 AGP·Kotlin 컴파일러/표준 라이브러리·Gradle이 필요합니다. Kotlin 소스를 설치형 앱으로 만드는 빌드 도구이며 처음 빌드할 때 공식 저장소에서 받아야 합니다. 지도·분석·광고·SNS SDK는 추가하지 않았습니다.

지도 데이터는 © OpenStreetMap contributors, ODbL-1.0입니다. [출처·데이터 라이선스](web/map-data/README.md)를 유지해야 합니다. 데이터 갱신 스크립트는 `scripts/fetch-map-data.mjs`이며 앱 실행 시에는 외부 지리 API를 호출하지 않습니다. Android 도구 검토 계획은 `docs/android-build-plan.json`에 있고, 사용자의 SDK 약관 동의를 받아 프로젝트의 `.build-tools` 폴더에 개발 도구를 준비하고 APK를 빌드했습니다.

참고 이미지는 색감·카드·메뉴 구성 참고로 사용했습니다. 타 앱 로고나 사용자 사진을 제품 자산으로 복사하지 않았고, 현재 산 이미지는 직접 제작한 SVG 일러스트입니다.
