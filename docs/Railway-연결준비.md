# Railway 연결 준비

사용자가 2026-11-05 무료 체험 진행을 선택했습니다. 계정 가입·약관 확인은 사용자가 직접 수행하고, 유료 결제·전환은 별도 동의합니다. 아직 공개 배포하지 않았습니다.

## 초보자 계정 준비 순서 · 2026-11-20 확인

1. https://railway.com/login 에 접속합니다.
2. Continue with GitHub로 본인 계정에 로그인합니다. Google 로그인도 가능합니다.
3. 서비스 약관과 이용 정책을 직접 확인하고 동의합니다.
4. 대시보드가 열리면 계정 준비가 끝납니다. 가입 준비를 위해 결제하거나 서버를 만들 필요는 없습니다.
5. GitHub 저장소 선택 화면에서 목록이 비어 있어도 계정 가입 실패를 뜻하지 않습니다. 로컬 파일 업로드로 배포할 수 있으며, 별도의 저장소 권한 확대는 이 단계에 필요하지 않습니다.

공식 문서 기준 신규 체험은 카드 등록 없이 30일간 일회성 $5 크레딧을 제공합니다. GitHub 계정 자동 검증 결과에 따라 외부 네트워크가 제한될 수 있습니다. 무료 체험 종료와 데이터 보존 정책은 [무료 플랜 공식 안내](https://docs.railway.com/pricing/free-plan)를 배포 시 다시 확인합니다. 유료 전환은 별도 동의 후 진행합니다.

GPS 기록은 기기 위치 기능이고 이 계정은 여러 사용자 간 계정·일정·후기를 보관할 서버를 위한 것입니다. Android 가상 기기의 모의 GPS 검증과 실제 산행 GPS 평가는 구분합니다.

## 계정 준비 후 필요한 것

계정 준비 여부만 알려주세요. 비밀번호·로그인 토큰을 대화에 보내지 마세요. 실제 서비스 생성·코드 전달 방식·권한은 연결 단계에서 확인합니다. GitHub 업로드/공개는 아직 하지 않았습니다.

## 서비스 설정안

| 설정 | 값 |
|---|---|
| 런타임 | Node.js 24 이상 (package.json engines와 실제 빌드 로그 확인) |
| 시작 명령 | node scripts/serve-production.mjs |
| 상태 검사 | /api/health |
| 공개 주소 | Railway가 발급한 실제 HTTPS 주소 |
| SANGIL_PUBLIC_ORIGIN | 공개 주소의 원점, 끝 슬래시 제외 |
| SANGIL_LISTEN_HOST | 0.0.0.0 |
| PORT | 호스팅이 제공하는 포트 사용 |
| 볼륨 | 서비스에 영구 볼륨 연결, 예: /data |
| SANGIL_DATA_DIR | /data 또는 연결된 볼륨 내부 |
| 복제 | SQLite를 사용하는 동안 단일 인스턴스 |

볼륨은 빌드 단계가 아닌 실행 시점에 연결됩니다. DB를 빌드/사전 배포 단계에서 생성하지 않습니다. Node 시작 스크립트가 실행 시 DB를 준비합니다. 볼륨 경로가 없거나 밖으로 지정되면 시작을 거부하도록 구현했습니다.

Railway의 현재 공식 문서는 신규 서비스에서 기존 railway.json/toml 방식을 사용하지 않도록 안내합니다. 이번 준비에서는 해당 파일을 추가하지 않고 서비스 설정을 명시합니다. 실제 생성 시 현재 콘솔과 문서를 다시 대조합니다.

## 연결 후 검사

1. HTTPS health가 열리고 배포 중 오류가 없는지 확인.
2. 웹에서 예시 계정·일정·후기 사진 생성, 재시작 뒤 지속 보존 확인.
3. 실제 주소로 앱 설정·재빌드한 뒤 두 기기의 서버 인증과 일정 공유 확인.
4. 세션 만료·로그아웃·비밀번호 변경·탈퇴 및 네트워크 오류 확인.
5. 저장량·백업·비용 사용량 확인. 체험 종료 시 계속 운영할지는 사용자가 결정.

## 서버 DB 백업 확인

서버와 같은 `SANGIL_DATA_DIR` 환경에서 `node scripts/backup-server.mjs <비공개 백업 폴더>`를 실행합니다. SQLite 백업 기능으로 실행 중인 서버의 데이터도 별도 폴더에 복사합니다. 해당 폴더의 `verified.json`에 무결성 검사 결과, 자료 개수와 SHA-256이 기록됩니다. 복원에 사용할 때는 이 기록이 있는 백업을 고르세요.

백업에는 계정·세션 정보와 후기 사진이 들어 있습니다. 웹에서 제공하는 경로나 Git 저장소 밖의 접근 제한 폴더에 보관하세요. 백업을 복원할 때는 `sangil.sqlite`를 새 비공개 데이터 폴더에 복사해 별도 로컬 서버에서 먼저 확인합니다. 현재 운영 DB의 파일을 직접 덮어쓰면 실행 중인 데이터와 충돌할 수 있습니다.

로컬 자동 검사에서 SQLite 서버 연결을 유지한 상태로 백업을 만들고, 백업 파일을 별도로 열어 후기와 사진 데이터가 보존됐는지 확인했습니다. Railway 볼륨에서 백업을 다른 저장소로 옮기고 재배포 후 복원하는 검증은 서버 개설 뒤 진행합니다.

공식 문서: [서비스 설정](https://docs.railway.com/config-as-code), [공개 네트워크](https://docs.railway.com/networking/public-networking), [지속 저장 볼륨](https://docs.railway.com/volumes).

## 로컬 배포 파일 사전 검사 · 0.8.6

`node scripts/prepare-server-package.mjs`는 `outputs/railway-server-날짜/`에 웹·서버 코드 46개만 복사합니다. 개인 계정 DB·산행 기록·개발 도구·Android 서명 파일·조사용 GPX/PDF는 포함하지 않습니다. 기존 결과 폴더를 덮어쓰지 않으며, 공개 웹 폴더에 비공개 파일이나 연결 파일이 섞이면 중단합니다. 함께 생성하는 manifest에는 포함 파일의 크기와 SHA-256이 있습니다.

배포용 package.json은 Node.js 24와 운영 시작 스크립트를 지정합니다. 서버의 health 버전은 이 package.json에서 읽으므로 앱 버전 갱신 시 예전 번호를 표시하지 않습니다.

자동 검사에서 이 묶음만 복사한 임시 폴더로 운영 시작 스크립트를 실행하고, 별도의 비공개 DB 폴더에 시험 계정·일정을 저장했습니다. 서버 재시작 후 세션과 일정 보존을 확인했습니다. 이는 로컬 검사이며 Railway 배포·공개 HTTPS 검증 완료를 뜻하지 않습니다.

Railway 공식 CLI 5.75.0의 계정 로그인은 작업공간·프로젝트·SSH 키 관리와 로그인 유지 권한을 요청했습니다. 해당 범위의 승인은 대기 상태입니다. 산길따라 전용 프로젝트 권한 또는 명시적으로 허용한 공식 CLI 계정 로그인으로 연결해야 하며, 토큰은 채팅에 보내지 않습니다. 유료 전환은 별도 동의합니다.
