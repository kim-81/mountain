# 산길따라 0.6.0 · 휴대폰 서버 연결 구현

갱신일 2026-11-05. 공개 서버 계정은 사용자가 Railway 무료 체험으로 준비하기로 했습니다. 이 버전의 기본 서버 주소는 비어 있으며 APK는 기기 저장 모드입니다. **공개 HTTPS와 실제 휴대폰 사이의 동기화 검증은 아직 완료되지 않았습니다.**

## 추가 코드

- Android: 지정된 HTTPS 원점으로 OS 통신을 수행하고 세션 토큰은 Android Keystore 키로 암호화해 저장합니다. JavaScript에는 토큰을 전달하지 않습니다.
- iPhone: 동일한 통신 계약과 Keychain 저장 소스를 추가했습니다. Mac이 없어 컴파일·설치 검증은 하지 못했습니다.
- 서버: 기존 웹 쿠키 인증을 유지하면서 네이티브 요청의 Bearer 세션 인증을 추가했습니다. 토큰 원문은 응답 본문에 넣지 않고 네이티브 통신 계층이 처리하는 헤더로 전달합니다. DB에는 해시만 저장합니다.
- 네이티브 표시는 앱의 진위를 증명하지 않습니다. 보호 대상 요청에는 유효한 토큰이 필요합니다. 네이티브 요청에 웹 Origin이 있으면 우회하지 않으며, 네이티브 모드는 쿠키 인증에 대체 의존하지 않습니다. CORS 허용 범위를 넓히지 않았습니다.
- 로그아웃·비밀번호 교체·만료된 세션을 처리하고, 현재 서버와 다른 주소로 토큰을 전달하는 리디렉션을 금지합니다.
- 연결 상태 버튼에 서버 설정 여부·오류·재확인 동선을 추가했습니다. 서버 저장 실패를 기기 저장 성공으로 바꾸지 않습니다.
- 공유 일정 링크는 지정 서버 주소를 사용합니다. 휴대폰 앱의 공유 일정 가져오기에 같은 서버의 링크를 붙여 넣을 수 있습니다. 다른 서버 링크는 거부합니다. OS 앱 링크 자동 진입은 별도 작업입니다.
- 운영 시작 스크립트는 Node 24·HTTPS 주소·Railway 지속 저장 볼륨이 준비되지 않으면 시작을 거부합니다.

추가 UI·통신·보안 라이브러리는 없습니다. Android HTTPS/Keystore와 iOS URLSession/Keychain 등 OS 기본 기능을 사용합니다.

## 확인한 것과 남은 것

자동 검사 42개 통과 대상: 두 계정의 네이티브 세션·일정 참가·후기 공유·소유권·위조 출처·쿠키 혼용 방지·비밀번호 갱신·로그아웃, 통신 응답 순서·시간 초과, 공유 링크 주소 검증, 운영 저장소 설정 및 기존 지도·기록 검사.

Android 소스는 실제 Kotlin 컴파일과 APK 빌드를 확인했습니다. 기본 APK의 서버 설정은 비어 있습니다. 네이티브 브리지 모의 검사와 로컬 HTTP 서버의 인증 검사는 실제 Android Keystore·HTTPS 통신·재설치/재시작 보존의 실기기 검증을 대신하지 않습니다.

미완료: 공개 HTTPS 배포, 실기기의 서버 로그인/공유, iOS 컴파일·서명, 실시간 데이터, 나머지 5개 기본 경로, 실제 GPS·알림·배터리 검증. 대량 후기·사진의 페이지 분할 및 운영 저장소 관리도 추가해야 합니다. native 응답 한도는 8MB, 요청 본문은 3MB이며 한도 초과 시 성공으로 표시하지 않습니다.

## 서버 주소가 준비되면

```powershell
node scripts/configure-server.mjs --origin https://실제서버주소
node scripts/sync-native.mjs
node --test tests/*.test.mjs
node scripts/build-android.mjs
node scripts/verify-android.mjs
```

기기 저장 모드로 되돌리는 명령은 `node scripts/configure-server.mjs --device-only`입니다. 설정 뒤에는 동기화·재빌드가 필요합니다. 서버 주소는 공개 설정이며 비밀 키나 비밀번호를 파일에 넣지 않습니다.

실제 공개 후에는 두 개의 예시 계정으로 일정 생성 → 다른 기기 참가 → 후기 사진 저장 → 재시작 → 로그아웃·비밀번호 변경·탈퇴를 확인해야 합니다. 위치 기록은 서버로 자동 전송하지 않습니다.
