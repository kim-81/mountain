# 0.8.7 · 공개 공유 서버 연결

2026-11-21 진행 기록입니다. 서울 기본 경로는 7/8곳이며 봉화산 경로와 현장 GPS 검증은 남아 있습니다.

## 공개 서버

- 주소: https://mountain-production-ae35ffea.up.railway.app
- GitHub `kim-81/mountain` 한 저장소만 Railway 공식 앱에 연결했습니다.
- Node 24.22.2, 시작 명령 `node scripts/serve-production.mjs`, 포트 8080, 상태 검사 `/api/health`입니다.
- SQLite 계정·일정·후기를 `/data` 지속 저장 볼륨에 보관합니다. 단일 인스턴스입니다.
- 무료 체험 범위로 배포했습니다. 카드 등록과 유료 전환은 하지 않았습니다. 체험 종료 후 운영 방침은 별도 결정이 필요합니다.
- Railway 상태 검사 전용 Host는 GET `/api/health`에만 허용합니다. 일반 화면·계정 API에는 해당 예외를 적용하지 않습니다. [공식 상태 검사 문서](https://docs.railway.com/deployments/healthchecks)

## 확인한 결과

- 자동 검사 71개 통과.
- Railway 배포 성공 및 실제 웹 화면의 ‘서버 연결’ 표시 확인.
- 공개 HTTPS에서 두 예시 계정으로 일정 생성, 참가 응답, 후기·사진 업로드와 공개 조회, 타인 삭제 차단, Secure 쿠키를 확인했습니다.
- 서버 0.8.6→0.8.7 재배포 후 기존 검사 계정·로그인 세션·일정 보존을 확인했습니다.
- Android 15 가상 기기의 0.8.7 APK에서 공개 HTTPS 상태 확인, 네이티브 회원가입, 보호 저장소 세션 인증, 검사 계정 정리를 확인했습니다. 실제 휴대폰 검증과 구분합니다.
- 실제 날씨 및 서울둘레길 공지 조회가 공개 서버에서 정상 응답했습니다.
- 정상 종료한 공유 검사에서 예시 계정·일정·후기를 정리했습니다. 최초 검사 도구의 탈퇴 확인값 누락으로 생긴 별도 예시 계정 2개는 비활성 상태로 남아 있습니다. 실제 개인정보는 사용하지 않았습니다.
- `node scripts/check-live-server.mjs https://mountain-production-ae35ffea.up.railway.app`로 공유 검사를 다시 실행할 수 있습니다. 이 명령은 예시 계정과 데이터를 만들고 정리합니다.

## 앱 변경과 남은 확인

- Android 15 가상 기기에서 0.8.6 체험 기록을 저장하고 0.8.7로 업데이트한 후, 확인을 거쳐 기록·즐겨찾기를 가져오고 같은 기록을 두 번 가져와도 1개를 유지하는 것을 검증했습니다. 원본 기기 보관함도 유지했습니다.
- 0.8.7 Android/iOS 공통 소스에 공개 HTTPS 서버 주소를 설정했습니다.
- 앱 ID는 `kr.seoultrail.app`을 유지하고 Android 버전 코드는 15로 올렸습니다.
- 이전 기기 체험 계정의 기록·즐겨찾기를 확인 후 현재 영역에 복사하는 화면을 추가했습니다. 원본을 유지하고 기록 번호가 같으면 중복 추가하지 않습니다.
- 기존 GPS 기록을 서버로 자동 업로드하지 않습니다. 계정·공유 기능과 기기 GPS 기록은 구분됩니다.
- 휴대폰 간 실제 공유, 실제 산행 GPS·배터리·화면 잠금 동작, iPhone 빌드·설치는 아직 완료로 판단하지 않습니다.
- 현재 웹 서버는 무료 체험 운영 단계입니다. 전국 확대는 서울 8곳의 경로 준비를 완료한 후 진행합니다.
