# 데이터 구성과 출처

## 데이터 단위

- `data.js`: 산 ID, 이름, 대표 위치, 카드 색상 등 장소 정보. 대표 위치 좌표는 초기의 근사값으로 실제 출발점 위치와 다릅니다.
- `catalog.js`: 대표 코스 ID, 산 ID 연결, 공식 거리·시간·난이도·출발/도착·경유지·원문 URL·확인일.
- `state.routes[mountainId]`: 사용자가 가져온 GPX 이름, 분리된 `segments`, 좌표 수·계산 거리·가져온 시각·`user-provided` 출처.
- `state.activeSession`: 진행 중인 산행, 시작 시각, 사용 경로 스냅샷, GPS 지점, 누적 거리, 이탈 감지 상태.
- `state.records`: 종료한 기록. 사용자가 완주를 확인하며 GPS만으로 완주를 판정하지 않습니다.
- `state.checklists`: 산별 출발 준비 체크 상태.
- SQLite `users / sessions / plans / responses / reviews`: 로컬 서버의 계정·세션·일정·응답·후기.

시설·상승고도·경사·날씨·통제에 확인되지 않은 값은 `null` 또는 `unknown`을 사용합니다. 0, ‘정상 개방’, ‘시설 있음’ 등으로 대체하지 않습니다.

## 저장과 이전 버전 호환

기기 저장 키 `seoul-trail-v1`는 데이터 보존을 위해 유지했습니다. 구버전 즐겨찾기·이력은 읽어들이며, 잘못된 타입의 데이터는 기본값으로 보완합니다. 서버 계정으로 전환할 때 개인 산행 기록과 즐겨찾기는 기기에 계정별로 분리합니다. 서버 데이터베이스는 `.local-data/sangil.sqlite`에 저장하며 Git에서 제외합니다.
